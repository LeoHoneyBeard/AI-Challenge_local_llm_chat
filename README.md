# AIChallenge Local LLM Chat

Мобильное приложение-чата на Kotlin/Compose, которое работает с локальной моделью через вшитый движок [llama.cpp](https://github.com/ggerganov/llama.cpp). Интерфейс копирует привычный мессенджер с ролями «пользователь/модель», история переписки хранится в Room и используется как контекст для генерации.

## Основные возможности
- Чат в стиле мессенджера с отправкой/приёмом сообщений и стримингом токенов.
- История сохраняется в базе и автоматически восстанавливается при перезапуске.
- Локальная LLM через встроенный `llama.cpp` (нативный код собирается при билде).
- Чистая архитектура с разделением на data/domain/presentation, use-case слой и отдельный движок LLM.
- Подробные подсказки по установке модели и требованиям к окружению.

## Подготовка модели
1. Скачайте любую *GGUF*-квантизованную модель. Рекомендованная и протестированная конфигурация:
   - **Название**: `phi-3-mini-4k-instruct-q4.gguf`
   - **Источник**: репозиторий [microsoft/Phi-3-mini-4k-instruct-gguf](https://huggingface.co/microsoft/Phi-3-mini-4k-instruct-gguf)
   - **Размер**: ~1.8 ГБ
   - **Квантование**: `Q4_K_M` или аналогичное Q4 (баланс скорости/качества для смартфона)
2. Поместите файл в каталог `app/src/main/assets/models/` и оставьте имя **точно** `phi-3-mini-4k-instruct-q4.gguf`.
3. При первом запуске приложение скопирует модель во внутреннее хранилище (`/data/data/<package>/files/models/`). Если файл отсутствует или повреждён, вы получите понятную ошибку в UI.

> Нужно использовать именно **GGUF**, потому что `llama.cpp` читает этот формат напрямую. Если хотите другую модель, обновите `LlmConfig.MODEL_FILE_NAME` и положите новый файл в assets.

## Зависимости и окружение
- Android Studio Giraffe+ c установленным **Android NDK 27.1** (Gradle скачает автоматически при синхронизации).
- Минимальная версия Android — 26 (Android 8.0).
- Собрание native части управляется через `CMakeLists.txt`, который добавляет исходники `third_party/llama.cpp`.
- Первая сборка может занять несколько минут из-за компиляции `llama.cpp`.

## Структура проекта
```
app/
 ├─ src/main/java/com/example/ai_challenge_local_llm_chat
 │   ├─ data/… (Room + repository)
 │   ├─ domain/… (модели + use cases)
 │   ├─ core/llm/… (движок llama.cpp, менеджер файла модели, prompt builder)
 │   ├─ presentation/chat/… (ViewModel + Compose UI)
 │   ├─ di/AppModule.kt (простой Service Locator)
 │   └─ MainActivity.kt
 ├─ src/main/cpp/ (CMake + bridge `llama-android.cpp`)
 └─ src/main/assets/models/ (сюда кладём *.gguf)
```

## Как запустить
1. Выполните `git submodule update --init --recursive` (если клонировали проект без папки `third_party/llama.cpp`).
2. Поместите модель как описано выше.
3. Откройте проект в Android Studio и дождитесь синхронизации Gradle/NDK.
4. Запустите `app` на устройстве/эмуляторе ARM64 (желательно реальное устройство из-за требований к памяти).

## UI/UX
- `ChatScreen` показывает сообщения, подсветку ролей и индикатор токенизации.
- `ChatViewModel` обеспечивает стриминг ответа и обработку ошибок; при отправке нового сообщения предыдущая генерация отменяется.
- Отдельная кнопка очистки истории.

## Архитектура и принципы
- **S**: у каждого use-case и репозитория одна ответственность.
- **O**: новая LLM может быть добавлена путём реализации `LocalLlmEngine`.
- **L**: доменные модели не знают о Room/Compose.
- **I**: интерфейсы (`ChatRepository`, `LocalLlmEngine`) отражают минимально необходимый контракт.
- **D**: presentation слой зависит от абстракций (use cases), а не от Room или llama.cpp напрямую. Простой `AppModule` выступает в роли DI-контейнера.

## Полезные команды
- Сборка: `./gradlew assembleDebug`
- Запуск unit-тестов (когда появятся): `./gradlew test`.
- Очистка истории в приложении: кнопка корзины в `TopAppBar`.
